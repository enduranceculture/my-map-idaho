# MYDAHO Elevation Profiles · V1

Shared, read-only terrain estimates for official USFS trails in Oakridge/Westfir, Wood River/Sawtooth, and Warm Springs/Bonneville. The canonical data is generated by \`scripts/build_elevation_profiles.py\` from the **browser-facing** GeoJSON named in \`data/catalog/base-v1.json\`, so the identity matches what MYDAHO displays.

## Provenance and safety

* DEM source: Mapzen/AWS Terrarium tiles (USGS-derived elevation), z13, ~45 m line sampling; median-filtered elevation and 3 m minimum-change threshold for cumulative gain/descent. Terrain estimates are not surveyed elevations or a guarantee of ride difficulty.
* Geometry: official USFS trails. Same identity as \`personalKeyForFeature()\` (source layer + normalized name + trail number; FNV1a 32, base36).
* Profiles are scoped to the longest **connected** component of a named trail. \`sourceComponents\` and \`sourceCoverage\` explicitly flag any disconnected source sections. No straight connectors are invented or counted toward gain/descent. Missing terrain tiles result in absent profiles, never fabricated heights.
* Samples are [distanceMeters, elevationMeters, longitude, latitude]. Values are in metric; clients convert for display.
* **Direction:** source geometry is not riding direction. UI offers reverse; reversing swaps gain/descent. START/FINISH are **profile geometry** endpoints, not official trailhead/access claims.
* Profile data is public shared geography; no user GPS/history, tokens, auth or personal records are included.

## Rebuild

The feature workflow \`.github/workflows/trail-elevation-profiles.yml\` builds profiles on pushes to the generation branch, then commits the generated file to that branch using the repository GITHUB_TOKEN. Merge the generated dataset to \`main\` only after reviewing coverage, QA stats, and representative tracks. The app reads the stable \`main\` URL and handles profile missing/network errors without misleading zeros.

Future: expand per selected area, expose a date/DEM versioned update policy, and compare calculated vertical stats against known ridden tracks. No backend migrations required.
